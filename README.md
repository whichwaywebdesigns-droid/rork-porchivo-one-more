# Porchivo

> **In plain English:** Porchivo gives residents, property managers, and building
> staff one calm, trustworthy place to track packages, deliveries, and handoffs —
> so everyone in a building stays aligned and nobody's left guessing where a parcel is.

**Platform**: Native iOS & Android app, exportable to web
**Framework**: Expo Router + React Native
**Backend**: Supabase (database, auth, edge functions)
**Marketing site**: separate web app in `web-porchivo-web/`

---

## What's inside (the short version)

Porchivo is made of two apps that live in this one project:

- **`expo/`** — the actual mobile app residents and staff use.
- **`web-porchivo-web/`** — the marketing website (the landing page people see before downloading).

The brain behind both — accounts, package data, notifications — lives in **Supabase**
(the `supabase/` folder). You deploy it with one script; see `supabase/DEPLOY.md`.

---

## The new onboarding & paywall flow

This is the polished first-run experience a new user sees. It's six calm screens,
in order, designed to feel premium and never pushy:

1. **Welcome** — brand mark, the headline, and a "Get started" button.
2. **Role selection** — "How will you use Porchivo?" (Resident, Property Manager, Staff, Other).
3. **Pain point** — "What do you want help with most?" (one quick tap).
4. **Value preview** — three benefit cards that personalize based on the answers above.
5. **Setup** — optional building name, unit, and notification preferences (skippable).
6. **Paywall** — a *soft* paywall that only appears **after** onboarding, never on first launch.

Good to know:

- **Answers are saved on the device** first, structured so they can later sync to Supabase.
- **The paywall is soft** — users can keep a limited free experience if they skip.
- **Nothing is loud or fear-based** — no crime stats, no countdown timers, no "BEST DEAL" stickers.

## Built-in A/B testing (so you can measure what works)

Porchivo now has a real experiment system so you can test ideas and see what actually
keeps users around — instead of guessing.

- **Flip variants live** — the active variant is controlled by a Supabase flag, so you can
  change which version users see **without shipping an app update**, including a kill switch
  and a rollout percentage.
- **Each user sticks to one variant** — assignment is sticky per device, so the experience
  doesn't flicker between versions.
- **Everything is measurable** — every action is stamped with the user's variant, an
  "exposure" event fires once when they see the welcome screen, and a daily "session" ping
  lets you compute Day-1 / Day-7 / Day-30 retention per group.
- **Results in one place** — a Supabase view shows each group's size, retention, and paywall
  conversion side by side, with a basic significance check before you call a winner.
- **Primary metric is locked up front** to avoid fooling yourself later: retention is the
  goal, paywall conversion is the guardrail.

The knobs you can experiment with: onboarding headline, value-preview copy, paywall timing,
annual-vs-monthly emphasis, plan layout, and trial-CTA wording.

## How can I deploy this project?

### **Publish to App Store (iOS)**

1. **Install EAS CLI**:

   ```bash
   bun i -g @expo/eas-cli
   ```

2. **Configure your project**:

   ```bash
   eas build:configure
   ```

3. **Build for iOS**:

   ```bash
   eas build --platform ios
   ```

4. **Submit to App Store**:
   ```bash
   eas submit --platform ios
   ```

### **Publish to Google Play (Android)**


For advanced native features, you'll need to create a Custom Development Build instead of using Expo Go.

### **When do you need a Custom Development Build?**

- **Native Authentication**: Face ID, Touch ID, Apple Sign In, Google Sign In


## Troubleshooting

### **App not loading on device?**

1. Make sure your phone and computer are on the same WiFi network
2. Try using tunnel mode: `bun start -- --tunnel`
3. Check if your firewall is blocking the connection

### **Build failing?**

1. Clear your cache: `bunx expo start --clear`
2. Delete `node_modules` and reinstall: `rm -rf node_modules && bun install`
3. Check [Expo's troubleshooting guide](https://docs.expo.dev/troubleshooting/build-errors/)

### **Need help with native features?**

- Check [Expo's documentation](https://docs.expo.dev/) for native APIs
